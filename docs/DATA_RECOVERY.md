# 数据恢复体验与验收口径

2026-09-10，适用于 1.2.5。产品目标：故障时仍能使用本次记录，用户不用猜文件位置，也不会在不知情时丢失旧数据。

## 正常使用

- 不展示恢复弹窗，不保留多代历史备份。历史与设置原子写入。
- 默认 10 条，最高 50 条；新记录入队后仅移除超出上限的最早记录。
- 文件增加 `schemaVersion: 1`。原始数组历史和无版本设置仍可加载。

## 保存暂时失败

- 保留内存中的当前记录，并提示“保存暂未完成，记录仍在”。
- 菜单“数据与恢复”标为“需要处理”；优先操作是“重试”，无需重新启动。
- 重试保存当前内存状态，不回退到旧磁盘状态，不重新导回已删除内容。
- 后续复制也会重新尝试保存。排队的旧保存回调不能覆盖新一次恢复结果。
- 未成功保存前退出仍可能丢失本次新增记录，界面明确提示暂存范围，不能宣称已经保存。

## 启动时无法读取

- 尽量展示仍可读取的历史；无法读取的原文件保持不变。
- 本次仍可采集、搜索、选择记录。重试成功后，将本次复制放在恢复历史之前，去重并限制 50 条。
- 重试过程尊重本次运行已经执行的单条删除或全部清空。
- 不把文件权限、磁盘故障误判为 JSON 损坏；更高格式版本提示使用更新应用。

## 明确损坏时的受控恢复

1. 用户打开“数据与恢复”，先看到重试和打开目录入口。
2. 选择“保留损坏文件并重建”后，说明只重建无法解析的文件；可读数据保留。
3. 用户选择“保留并恢复”，先把所有损坏源文件完整保存到 `Recovery/<随机标识>/`。
4. 原文件留存全部成功后，才重建损坏的历史/设置。若归档失败，不覆盖源文件。
5. 成功后反馈恢复完成，保留本次新复制及可读数据。

只在用户明确恢复时生成原文件留存，不做自动历史回滚。Recovery 内容可能包含原剪贴板数据，权限限制到当前用户；它不会被自动导入。用户如不再需要留存，可通过打开数据目录自行删除。日常清空作用于活动历史，不承诺清除用户此前明确保留的原文件副本。

## 验收

自动化覆盖：健康数据不变、损坏历史/设置分别恢复、归档失败保护、旧路径损坏、未来格式保护、原文件字节一致、权限、重试后的新复制/去重/删除/清空。

实机已验证损坏历史的完整菜单流程：原文件字节保留，本次复制仍在，设置保持原值。更多状态见 [验收记录](ACCEPTANCE.md)。
