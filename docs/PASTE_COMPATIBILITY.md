# 粘贴兼容性修复记录

日期：2026-09-14。

## 问题与证据

用户反馈微信中双击、回车无法直接粘贴，ChatGPT 中似乎正常。

- 原运行应用为 1.6.0，构建 `2867C4E5-3272-486D-9102-C94476CCD38F`，路径、签名、哈希核对通过，辅助功能和模拟按键权限均开启。
- 增强诊断构建 `D6202BA6-652E-4BA1-8B79-1124F3553074` 的实际诊断显示 `目标程序不可用 [deliver-paste]`，说明该次请求已进入提交粘贴阶段。双击不会更新“回车路径”，因此“尚未接收回车”不代表双击未触发。
- 微信暴露的系统“编辑 → 粘贴”菜单显示禁用。该次菜单检查没有证明聊天输入框的实际可编辑状态，不能单凭菜单快照认定微信复现根因。
- 源码 `NativePasteCommand.deliver` 原先遇到 `.disabled` 直接返回 `.unavailable`，不尝试键盘粘贴。这条规则已存在于仓库最早的应用提交 `4ed6498`；不能归因于最近增加收藏或多语言。
- 原诊断目标名称来自当前面板目标；失败后重新打开面板可能重捕获前台应用，导致显示的目标与失败请求不一致。本次改为保留请求发生时的目标名称。

## 实现

当菜单缺失或禁用、且尚未执行粘贴动作时，允许一次键盘回退。发送前重新确认模拟按键权限、原应用仍在前台、物理按键已松开、剪贴板版本未变化。

菜单成功执行时立即完成；菜单超时或其他不确定结果不发送第二次粘贴。键盘事件提交也仅代表提交成功，仍须检查真实目标输入框。

诊断增加 `validate-target`、`prepare-clipboard`、`release-keys`、`activate-target`、`wait-target`、`restore-input-focus`、`deliver-paste` 阶段，不记录用户输入内容。
